# M4 Marks & Export (ส่งตรวจ)

ผลทดสอบล่าสุด: Unit Tests 135 รายการผ่าน, E2E 62 ขั้นตอนผ่าน (M1 24, M2 16, M3 12, M4 10) รันด้วย Chrome บน Windows

## ทำได้แล้ว

- Registration Marks 3 กลุ่ม: MicroCut 30Q - Custom 5 Dots (Unverified), วงกลม 3/4 จุด, มุม L 4 มุม ปรับขนาด ระยะจากขอบ ระยะสงวน และความหนาก่อนสร้างได้
- มาร์คกำหนดเอง: วงกลม สี่เหลี่ยม กากบาท มุม L เพิ่ม ลบ ทำซ้ำ ลากย้าย หมุน ปรับขนาด กรอก X,Y เป็น มม. ล็อก จัดแนวกับขอบกระดาษ สีเติมหรือเส้นขอบ
- บันทึกชุดมาร์คเป็น Profile ของผู้ใช้ และนำกลับมาใช้หลังรีโหลดได้
- พื้นที่สงวนรอบมาร์คกันทั้ง Auto Layout, Nesting และการลากเอง
- โหมดแสดงผล: ภาพ+เส้นตัด, ภาพอย่างเดียว, เส้นตัดอย่างเดียว และเปิดปิดเส้นช่วย มาร์ค เส้นตารางแยกกัน อยู่ในเมนู "มุมมอง"
- ส่งออก PNG (150/300/600 DPI โปร่งใสหรือขาว), JPG พื้นขาว, PDF ขนาดหน้าจริง ทุกไฟล์ฝังค่า DPI จึงพิมพ์ได้ขนาดจริง
- Print + Marks: เลือกใส่มาร์คในไฟล์พิมพ์
- Cutline SVG: Path จริงในกลุ่ม `CUT_LINES` ขนาดเป็น มม. viewBox ตรงกระดาษ เลือกใส่มาร์คเป็นชั้นอ้างอิงที่ระบุว่าไม่ใช่เส้นตัดได้
- Combined SVG: `ARTWORK` / `CUT_LINES` / `REG_MARKS` แยกกลุ่ม
- หลายหน้าหรือหลายไฟล์รวมเป็น Zip ชื่อ ชื่องาน_p01_ชนิด
- Preflight ตรวจขนาดจริง, Margins, Overlap, Spacing, Keep-out, DPI, เส้นตัด, Marks และขนาดภาพก่อนส่งออก ถ้ามีข้อผิดพลาดต้องติ๊กยืนยันก่อน
- ส่งออกมี Progress และยกเลิกได้
- Bleed พิมพ์จริงแล้ว โดยยืดพิกเซลขอบภาพออกไปตามระยะ Bleed ทั้งบนจอและในไฟล์
- หน้าจอและไฟล์ส่งออกใช้ตัววาดชุดเดียวกัน ไม่จัดเรียงใหม่ตอนส่งออก
- AC-11: ศูนย์กลางเส้นตัดใน SVG ตรงกับภาพใน PNG 300 DPI คลาดสูงสุด 0.014 มม. (เป้าหมาย ≤0.1 มม.) วัดจากไฟล์ที่ส่งออกจริงด้วยตัวถอดรหัสภาพของเบราว์เซอร์

## ปรับตามข้อมูลจาก SignMaster (2026-11-16)

- ระยะขอบของชุดมาร์คเปลี่ยนเป็นระยะจากขอบกระดาษถึงจุดกึ่งกลาง ตั้งแยก 4 ด้าน เหมือน Page Mark Margins ของ SignMaster ค่าเริ่มต้น MicroCut 10/10/10/40
- จุดที่ 5 อยู่ใต้จุดบนซ้าย 20 มม. และเพิ่มสามเหลี่ยมบอกทิศทางกลางขอบบน (รูปมาร์คใหม่ "สามเหลี่ยม")
- จัดแนวมาร์คใช้ระยะขอบชุดเดียวกัน
- Preflight เตือนชิ้นงานที่อยู่นอกกรอบที่ล้อมด้วยมาร์ค
- มี Unit Test เทียบพิกัดกับ PDF จาก SignMaster ทุกจุด

## บั๊กที่พบจากการทดสอบรอบนี้และแก้แล้ว

- แถบเครื่องมือยาวเกินจอ 1360 px หลังเพิ่มปุ่ม หน้าเลื่อนแนวนอนได้ ย้ายตัวเลือกการแสดงผลไปเมนู "มุมมอง" และให้แถบขึ้นบรรทัดใหม่เมื่อจอแคบ
- เบราว์เซอร์ขอ favicon แล้วได้ 404 ใส่ไอคอนในหน้าแล้ว

## ข้อจำกัดที่ทราบ

- **มาร์ค MicroCut 30Q ยังไม่ได้ทดสอบการอ่านกับเครื่องจริง** ขนาดและตำแหน่งตรงกับ PDF ที่ SignMaster สร้าง (Teneth MC350CCD, ARMS CCD 5mm, Super A3, Page Mark Margins 10/10/10/40) ภายใน 0.01 มม. แล้ว แต่ SRS ข้อ 11 ยังเหลือการทดสอบตัดจริง จึงคงชื่อ Unverified และแสดงคำเตือนใน Preflight
- ระยะจุดที่ 5 (20 มม.) และสามเหลี่ยม (ด้าน 4 มม. ฐานเหนือแนวจุดบน 2 มม.) ได้จากไฟล์ตัวอย่างเดียว ยังไม่รู้ว่า SignMaster เปลี่ยนค่าเหล่านี้ตามขนาดกระดาษหรือ Margin หรือไม่
- SignMaster มีค่า Mark Spacing (แนวตั้ง 300 มม.) ที่อาจเพิ่มจุดกลางด้านเมื่อกระดาษยาวมาก ไฟล์ Super A3 ไม่มีจุดกลางด้าน โปรแกรมนี้จึงยังไม่สร้างจุดกลางด้าน
- ยังไม่ได้ทดสอบกับเครื่องตัดและเครื่องพิมพ์จริง
- PDF เป็นภาพ Raster ตาม DPI ที่เลือก ไม่มีเส้นตัดใน PDF ไฟล์ตัดใช้ SVG
- Combined SVG ฝังภาพทั้งหน้าเป็น PNG ไฟล์จึงใหญ่ (A4 300 DPI ราวหลาย MB)
- Bleed ยืดพิกเซลขอบภาพ ภาพที่ขอบโปร่งใส (PNG ตัดพื้นแล้ว) จึงไม่เห็นผล Bleed
- สีเป็น sRGB จาก Canvas ไม่มีการแปลง CMYK
- ส่งออกทำในหน้าหลัก หน้าใหญ่ ๆ หน้าจออาจหยุดชั่วครู่ระหว่างเข้ารหัสภาพ ปุ่มยกเลิกมีผลระหว่างขั้นตอน
- เบราว์เซอร์สร้างภาพได้ไม่เกินราว 268 ล้านพิกเซล A0 ที่ 600 DPI จึงส่งออกไม่ได้ Preflight แจ้งและบล็อก
- พื้นที่สงวนของมาร์คที่หมุนใช้กรอบหลังหมุน จึงกว้างกว่ารูปจริงเล็กน้อย
- เลือกมาร์คได้ทีละตัว จัดแนวเทียบขอบกระดาษเท่านั้น
- Profile ของผู้ใช้เก็บใน localStorage ของเบราว์เซอร์นี้ ย้ายเครื่องได้เมื่อมี Project File (M5)
- ยังไม่ได้ทดสอบ Edge และ Firefox

# M3 Layout & Nesting (ปิดงานแล้ว ผู้ใช้ตรวจครบทุกข้อเมื่อ 2026-11-12)

ผลทดสอบล่าสุด: Unit Tests 118 รายการผ่าน, E2E 52 ขั้นตอนผ่าน (M1 24, M2 16, M3 12) รันด้วย Chrome บน Windows

ผู้ใช้ทดสอบกับภาพจริง 3 แบบ 2 หน้า พร้อมพื้นที่ห้ามวาง: จัดให้ประหยัด, ระยะห่าง, Keep-out, หลายหน้า, รายงาน, ยกเลิก, Undo และ Bleed ผ่านทุกข้อ

## ปรับตามคำขอผู้ใช้หลังตรวจ

- ช่องกรอกตัวเลขทุกช่องมีปุ่ม ▲▼ และกดลูกศรขึ้น/ลงในช่องได้ (Shift ×10, Alt ×0.1) ค่าที่ได้ผ่านการตรวจขอบเขตเหมือนการพิมพ์ และ Undo ได้
- แสดงหน่วยท้ายช่อง: mm, ° สำหรับมุมหมุน และ "ชิ้น" ที่จำนวน
- ก้าวของปุ่ม: 1 mm สำหรับกระดาษ ตำแหน่ง ขนาด Keep-out, 0.5 mm สำหรับ Margin ระยะห่าง Bleed และ Offset, 1° สำหรับมุมหมุน
- ช่องจำนวนใช้ปุ่ม − + เดิม ไม่เพิ่ม ▲▼ ซ้ำ; แถบเลื่อนในตัวแก้เส้นตัดยังเป็นแถบเลื่อน

## ทำได้แล้ว

- เรียงตามแถว: ตามลำดับรายการหรือขนาด
- จัดให้ประหยัด: Nesting จากรูปร่างจริงด้วย No-Fit Polygon หมุนตามมุมที่เลือก
- ระยะห่างวัดจากเส้นตัดหรือขอบภาพ ค่าเริ่มต้น 3 มม. ตรวจทั้งตอนจัดอัตโนมัติและจัดเอง
- พื้นที่ห้ามวางหลายจุด ลากเข้าไม่ได้ และ Auto Layout ไม่ทับ
- หลายหน้า: เพิ่ม ลบ สลับ และเพิ่มเองเมื่อไม่พอ
- รายงานจำนวนวางแล้ว วางไม่ได้ จำนวนหน้า พื้นที่ใช้และว่าง
- Bleed ต่อแบบ มีผลกับการกันขอบและการกันทับ
- ผลจัดเรียงถูกตรวจซ้ำกับรูปเต็มก่อนใช้ ไม่ผ่านจะไม่นำมาใช้
- มี Progress ยกเลิกได้จริง และ Undo ทีเดียว
- ภาพพื้นทึบถูกตัดตามเส้นตัด พื้นหลังจึงไม่ทับชิ้นข้างเคียง

## บั๊กที่พบจากการทดสอบรอบนี้และแก้แล้ว

- Clipper บวก Minkowski เฉพาะเส้นขอบ ทำให้เกิดรูกลาง NFP และชิ้นงานซ้อนทับกันทุกชิ้น
- ค่าปัดเลขของ Clipper ทำให้ชิ้นชิดขอบล้นพื้นที่และแตะ Keep-out เล็กน้อย
- งานจำนวนมากช้า แก้ด้วยการจำหน้าที่เต็มแล้วและลดจุดตอนค้นหา

## ข้อจำกัดที่ทราบ

- Nesting ไม่รับประกันการจัดที่ดีที่สุด (FR-05.8) ใช้การวางทีละชิ้น
- เวลาขึ้นกับจำนวนแบบ × มุมหมุน × จำนวนจุด ไม่ใช่จำนวนชิ้นอย่างเดียว ทดสอบ 3 แบบ ทุก 90°: 120 ชิ้น ราว 17 วินาที, 3 แบบ ทุก 30° ช้ากว่าหลายเท่า ใช้งานจริงควรเริ่มที่ทุก 90°
- ชิ้นเล็กไม่ถูกวางในช่องปิดกลางชิ้นใหญ่ (เช่น รูวงแหวน) แต่ยังเข้าไปในรอยเว้าที่เปิดอยู่ได้
- ระยะห่างตอนจัดเองเป็นคำเตือน ไม่บล็อกการลาก ส่วนพื้นที่ห้ามวางบล็อกจริง
- หมุนหรือแก้ขนาดจนทับพื้นที่ห้ามวาง: แจ้งเตือน ไม่บล็อก
- Standard Layout วัดจากกรอบ จึงเว้นระยะมากกว่าค่าตั้งได้ และไม่หมุน
- กรอบเลือกอาจยื่นเลย Margin ได้ เพราะส่วนโปร่งใสของภาพไม่นับ ตัวชิ้นงานจริงยังอยู่ในพื้นที่
- Keep-out เป็นสี่เหลี่ยม กำหนดด้วยตัวเลข ใช้เหมือนกันทุกหน้า
- จัดเรียงทำกับทุกชิ้นทั้งโปรเจกต์ ยังเลือกเฉพาะบางชิ้นหรือตรึงบางชิ้นไว้ไม่ได้
- ยังไม่ได้ทดสอบ Edge, Firefox และเครื่องตัดจริง

# M2 Cutline Engine (ปิดงานแล้ว ผู้ใช้ตรวจเส้นกับภาพจริงเมื่อ 2026-11-05)

## ทำได้แล้ว

- ตรวจขอบจาก Alpha ปรับค่าได้ และแยกสีพื้นหลังด้วยการเลือกสีจากภาพ
- โหมดขอบนอก รวมเส้นเดียว และทุกเส้น (มีรู)
- ลด Noise, ลดรอยหยัก และได้ SVG Path ปิดแบบ Cubic Bezier ดาวน์โหลดรายแบบได้
- ความมนของมุมเป็นรัศมีจริง (เริ่มต้น 1.5 มม.) และความเรียบของเส้น (เริ่มต้น 0.6 มม.)
- Offset บวกและลบด้วย Clipper2 ค่าเริ่มต้น +2 มม.
- ตรวจเส้นซ้อนตัวเอง เส้นเล็ก และ Offset ที่ทำให้เส้นหาย
- แก้จุดเอง: ย้าย เพิ่ม ลบ ย้อน ล้าง
- คำนวณใน Web Worker มี Progress และยกเลิกได้จริง
- สร้างเส้นตัดทุกแบบในครั้งเดียว Undo ทีเดียว
- แก้ขนาดแล้วคำนวณเส้นใหม่อัตโนมัติ ระยะ Offset คงเดิม
- แสดงเส้น Magenta บนกระดาษด้วยเมทริกซ์เดียวกับภาพ เปิด/ปิดได้
- กัน Margin จากกรอบรวมภาพและเส้นตัด

## บั๊กที่พบจากการทดสอบรอบนี้และแก้แล้ว

- โหมดรวมเส้นเดียวแยกกลับเป็นสองเส้นหลังหด
- ระยะเกณฑ์ ≤0.1 มม. ทดสอบกับภาพละเอียดระดับงานพิมพ์ ไม่ได้ขยายเกณฑ์
- ผู้ใช้พบว่าเส้นเป็นเส้นตรงต่อกันและมุมเหลี่ยม แก้เป็น Bezier และลบมุมแล้ว มุมหักของภาพทดสอบลดจาก 178° เหลือ 15°
- ตัวแก้เส้นตัดมีแถบเลื่อนแนวนอน และปุ่มใช้เส้นตัดตกจอ

## ข้อจำกัดที่ทราบ

- ความแม่นยำขึ้นกับความละเอียดภาพ ราว 1 พิกเซล ผ่าน ≤0.1 มม. ที่ราว 300 DPI ถ้าต่ำกว่านั้นโปรแกรมจะเตือน
- วิเคราะห์ภาพด้านยาวไม่เกิน 2000 px ภาพใหญ่มากจะถูกย่อตอนตรวจขอบ เช่น ด้านยาว 297 มม. ละเอียด 0.15 มม. ต่อพิกเซล
- เส้นโค้งฟิตด้วยค่าคลาดเคลื่อน 0.05 มม. รวมกับความคลาดเคลื่อนจากภาพ
- ความมนของมุมเว้าทำให้เส้นถอยออกจากภาพบริเวณรอยเว้า ขอบสติกเกอร์ตรงนั้นจึงกว้างกว่าค่า Offset
- ค่าความมนสูงมากจะปิดรอยเว้าแคบ ๆ
- เครื่องตัดบางรุ่นหรือซอฟต์แวร์บางตัวอาจแปลง Bezier เป็นเส้นตรงเองตอนนำเข้า ต้องทดสอบกับเครื่องจริง
- แก้จุดได้เฉพาะจุดของ Contour ไม่มีเครื่องมือวาดเส้นเองทั้งเส้น
- แก้จุดแล้วค่าตรวจขอบถูกล็อกจนกว่าจะล้างการแก้
- แยกสีพื้นหลังเริ่มจากขอบภาพ พื้นหลังที่ถูกล้อมอยู่ในชิ้นงานจะไม่ถูกแยก ภาพถ่ายซับซ้อนควรใช้ PNG โปร่งใส
- Bleed มีผลกับการจัดวางแล้ว (พิมพ์ Bleed จริงทำใน M4)
- SVG ในตัวแก้เส้นตัดเป็นรายแบบเพื่อตรวจเส้น (ไฟล์ทั้งแผ่นอยู่ในหน้าต่างส่งออกของ M4)
- ยังไม่ได้ทดสอบกับเครื่องตัดจริง และยังไม่ได้ทดสอบ Edge และ Firefox
- Clipper2-WASM ใช้ไฟล์จากแพ็กเกจ npm ตรง ๆ ไม่ได้ Build เอง

## แก้จากรอบแรกหลังเทียบ SRS

- A3+ เป็น 320 × 450 และเพิ่ม Super A3 329 × 483 พร้อมคำอธิบาย
- Data Model เป็น Master/Instance ตาม SRS ข้อ 5
- จำนวนตั้งเป็น 0 ได้
- เปลี่ยนกระดาษหรือ Margin ไม่ย้ายชิ้นงานเองแล้ว แต่แจ้งชิ้นที่ผิด พร้อมปุ่มย้ายกลับ
- กระดาษเต็มไม่วางซ้อนแล้ว ชิ้นที่เกินเป็น "ยังไม่ได้วาง"
- เพิ่มเลือกหลายชิ้น, ลากคลุม, ย้ายเป็นกลุ่ม, Duplicate, Align, จัดลำดับชั้น
- เพิ่มเส้นตาราง, ตั้งระยะขอบเท่ากันทั้งสี่ด้าน, ข้อมูลไฟล์ในรายการ
- ลากไฟล์ลงกระดาษแล้วภาพอยู่ตรงจุดที่ปล่อย
- ลากมุมจนล้นแล้วหยุดชิดขอบพอดี และมี Feedback เมื่อถูก Clamp
- ระยะห่างเริ่มต้น 3 มม.

## บั๊กที่พบจากการทดสอบรอบนี้และแก้แล้ว

- ข้อความแจ้งเตือนบังการคลิกบนกระดาษ
- ลากมุมเร็วจนเฟรมแรกล้นแล้วชิ้นงานไม่ขยายเลย

## ข้อจำกัดที่ทราบ

- ทดสอบเฉพาะ Chromium ยังไม่ได้ทดสอบ Edge และ Firefox
- ชิ้นใหม่หาที่ว่างด้วยกรอบสี่เหลี่ยม ใช้ปุ่มจัดเรียงเพื่อจัดจริง
- ไม่มีมือจับหมุนบนจอ หมุนด้วยตัวเลขหรือปุ่ม 90° ซึ่ง SRS ไม่ได้บังคับ
- ลากมุมใช้ได้เมื่อเลือกชิ้นเดียว
- แสดงข้อความแจ้งเตือนพร้อมกันได้ 3 ข้อความ ถ้าไฟล์เสียหลายไฟล์ ข้อความเก่าจะถูกแทน
- `scaleX/scaleY` มีในโมเดลและเมทริกซ์ แต่ยังไม่มี UI และลากมุมรองรับเฉพาะค่า 1
- อ่าน DPI ของ JPEG จาก JFIF เท่านั้น ยังไม่อ่านจาก EXIF
- งานเก็บในเบราว์เซอร์เครื่องนั้น การล้างข้อมูลเว็บทำให้งานหายจนกว่าจะมี Project File (M5)
